NineRealms generation recovery v7

Scope
Based on the delivered v6 working copy; GitHub main checked unchanged at 39725d94f5a55c8daa010e7f5d7407c6cb3c1938. No commit or push.

Bounded recovery policy
Primary generation retains its existing rules. Explicit opt-in recovery is used by free-play new-game requests; frozen daily identities and fixed main-story/curated puzzles are unchanged. Each request keeps mode and requested tier. Failure or worker timeout may try a separate fresh source search, then a finite strictly verified reserve/catalogue. No candidate may bypass uniqueness, grading or recent structural exclusion. If nothing qualifies, the original game is retained with an honest retry message.

Budgets
Worker watchdogs: primary 8 seconds, fresh retry 8 seconds, finite reserve/catalogue 4 seconds. These are work-stage budgets, not a guarantee against browser background throttling or an unresponsive operating system. Cancel applies to every stage. No infinite retry loop.

Reserve inventory
216 fixed puzzles cover all 32 fresh-supported modes at all three tiers (at least two per mode/tier). Classic and king hard have eight each; disjoint, thermo, XV, greater, lockout and Xsum hard have four. All were selected from archived v5 audit output and independently re-proven, not newly generated by pretending the earlier seeds reproduce identical boards. All 216 canonical base signatures are distinct; 148 marked/jigsaw layouts are distinct across tiers. Multi-grid comparison uses conservative component spectra, not a full joint-graph isomorphism proof.

Compatibility and UI
Recovery provenance survives saves, history and backup import with independent validation; malformed provenance is not trusted as proof. Existing rules panel identifies fixed reserve/catalogue versus new search without adding controls. The same-rule new-puzzle practice entrance deliberately permits fresh retry only (8+8 seconds), never a fixed reserve advertised as new. Initial launches, master puzzles, fixed story content and frozen daily history do not adopt this new free-play policy.

Quality and limitations
A fixed reserve is explicitly identified as a finite pre-verified puzzle, not newly generated content. Runtime validation is repeated before serving. Supported Hints modes preserve exact logical tiers; other supported variants preserve rule-path/quality criteria, not a claim of human-playtested difficulty. Canonical recently used bases and rule layouts remain excluded, so reserve exhaustion is intentional rather than permission to repeat or lower difficulty.

Verification
Focused reserve, generator recovery, actual Node worker, backup and DOM tests passed. Full npm test, test:dom, verify and git diff --check passed on final production code. Full regression includes 10,128 valid catalogue outputs with independent uniqueness checks, 129 unchanged expected old-generator budget declines, the 32 x 3 x 3 fresh-generation matrix, and frozen daily golden/history checks. The bounded audit passed: 200 independent classic/king hard requests all passed the primary path; these do not establish an improved natural failure rate. All three known v6 failing classic seeds were rejected by the unchanged primary, then recovered by fresh retry. Each of 99 mode/tier cells was independently probed at both recovery stages: 96 fresh retries accepted (miracle unsupported), 97 fixed-stage acceptances, with miracle medium/hard honestly unavailable. There were no invalid deliveries, unexpected errors, over-stage-budget samples or source drift. Detailed timing and raw evidence are in docs/fallback-audit. This round has no Windows/mobile or real-browser pixel acceptance; DOM and worker-thread execution are not described as real-device measurements.
