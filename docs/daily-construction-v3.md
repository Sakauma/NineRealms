# 每日新构造与固定内容练习

## 不重写已发布题目

- 原 16 个主线关卡 ID、题面和星数规则保持不变。已完成章节的“同规则新题 · 独立练习”另开练习棋局，不带章节 ID，也不写入每日成绩。
- 精选原题仍可重玩；规则弹窗新增“生成同规则新题”，不会把新题冒充为原精选题。
- 两个入口先确认并核实当前棋局/历史可安全保存，再启动生成。取消、超时或质量检查失败均保留原棋局，不悄悄换成旧题库题。

## 每日 v3

从北京时间 `2026-11-15` 起，日期按经典、温度计、对角线、杀手笼、窗口、箭头、骑士、温笼交替轮换，使用 `nine-realms-daily-v3:YYYY-MM-DD` 种子构造新题。每天只有一道确定的题；不会因本地历史、玩家水平或“再次打开”更换题目。

生成策略由独立 `daily-generator-v1.js` 冻结，仍产出 generation v3。普通新游戏的 generation v4 与规则推演层级改进不会重排这批每日日期。该冻结策略仅使用无墙钟评分的基础规则推理与固定节点/尝试预算。未来规则引擎语义变更仍需通过日期 golden 测试；若会改变结果，应另设新日期版本，不能静默改题。

模块有 32 项 LRU 结果缓存，缓存返回副本，不写入用户存储。清除或逐出缓存不改变题面。

## 明确的后备与恢复

只有固定节点/尝试预算或规则参与检查这类确定性失败，才选用同模式的固定后备题（纯规则使用固定 seed 的旧版题库池，标记变体使用固定编号精选题）。界面明确显示“固定后备题，并非新生成题”。资源缺失、未知错误或墙钟超时不会被转换成另一道每日题。

旧日期保持原身份；旧版已经开启的未来 v1/v2 日期同样精确匹配并可恢复。匹配会先检查旧身份，不要求新生成器可用。日期、模式、给定数和完整规则标记均须吻合，不能只凭日期认领成绩。完成记录仍按日期保留第一次成绩，不因版本切换重复累计。

## 验证范围

- `tests/daily-constructed.test.cjs`：40 个日期的合法唯一解、基础规则路径、有效约束、完整经典对称群底盘与 D4 布局互异；11 个固定 golden 日期、跨年/闰日、极端墙钟、LRU、显式后备以及 v1/v2/v3 备份/历史恢复。
- `tests/daily-constructed-dom.test.cjs`：新每日开局、旧未来棋局继续、缺资源和后备文案。
- `tests/fixed-content-practice-dom.test.cjs`：主线星数不变、精选另开新题、真实 worker、确认/取消/失败与保存保护。

这些样本证明当前版本的实现与样本多样性，不是“未来所有日期永不重复”的数学保证。DOM 测试不等同像素或原生浏览器验收。

## 异步准备（不改变每日 v3 内容）

首次显示每日卡片只读取日期对应的玩法和轻量缓存，不在主线程构造题面。点击准备后，独立 worker 运行原封不动的冻结策略。现有“准备”按钮在工作中变为“取消准备”；关闭弹窗也会取消。取消后的晚到结果不写入缓存或棋盘，跨北京时间零点的结果不会替换当前对局。前后两次保存核验均成功后才换盘。

缓存仍最多 32 个日期，命中时不再启动 worker。未知错误、资源不可用或 8 秒看门狗超时只提供重试，不改变日期对应题面，也不冒充为确定性后备。

新版本每日存档在启动和历史恢复时会先尝试用 worker 预热严格身份校验所需的缓存。旧 v1/v2 身份无需新构造。为保留既有恢复能力，worker 不可用/失败时，存档恢复仍保留原有同步严格校验退路；批量备份校验中的同步身份核验也未改为 worker。因此本次消除的是日常卡片渲染与首次主动准备的同步构造，并非承诺所有历史/备份验证都完全没有主线程工作。

新增 `tests/daily-async.test.cjs` 验证真实 worker 的 11 个已交付 golden、事件循环可响应、缓存、取消/替换/晚到/错误结果、超时及资源清理。`daily-constructed-dom` 增补首开不生成、缓存重试、两次保存失败、跨午夜与异步恢复检查。

尚未在低性能实体设备上测量启动时间、worker 峰值内存和 8 秒超时触发率；Node worker 与 jsdom 测试不替代这类设备实测。若设备多次超时，应保留原局并重试，而非把超时解释成该日期存在另一道合法每日题。
